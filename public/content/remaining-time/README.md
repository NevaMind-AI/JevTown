# 26 房间内容包

默认通过 `just dev` 或 `npm run play:local` 启动，从 404 号舱开始。酒馆内容及餐饮、演出、教学仅在
`experiment/tavern-agentic` 实验分支保留，主线不再提供酒馆入口。

当前内容包括 26 张房间背景、54 个单向门／电梯连接（27 对双向连接）、5 个房间的 174 件独立物件，以及按原型位置放入 14 个房间的 32 个 NPC 实例。WASD／方向键移动，Shift 冲刺，走入出口格切换房间；靠近 NPC 时高亮，按 E 打开交互菜单。已接入 S01 从门牌观察到柜中暂存的六步强引导调查，其他来源地图剧情仍待编排。

## 数据入口

- `manifest.json`：内容版本 `room-world-7-s01-guided-2`、起始点与 Scene／Story 清单。
- `scenes/*.json`：出生点、返回落点、门的实体和目的地。
- `stories/travel.json`：各门的通行效果与分段时钟。
- `stories/npcs.json`：未单独编写对白的驻留 NPC 基础交互入口。
- `stories/s01-door-tag.json`：六步顺序调查、每步背景和操作指引、目标标记、门牌拿取与柜中暂存。
- `stories/unit-404.json`：404 床铺的睡眠交互。
- `src/content/remaining-time/maps/*.json`：通行网格、背景、物件图层与角色显示比例，沿用现有地图 JSON 加载机制。
- `public/assets/<scene-id>/`：背景、独立物件 PNG 与来源布局。
- `art/props/unit-404/`：20 份独立 Aseprite、原始布局与物件回拼图。
- `art/room-portals.json`：传送物件的格子位置、外观、目的地，以及各房间出生／返回点。
- `art/room-npcs.json`：原型 NPC 定义与驻留位置；像素脚点、接近点、职责及显隐规则保留原值。
- `public/assets/room-npcs/`：29 套原始透明图集及动作 JSON，待机首帧用于图集加载期间或加载失败时的显示。

生成配置位于 [`art/room-maps.json`](../../../art/room-maps.json)，读取各资产目录 `layout.json` 内的
`sourceLayout`。更新后运行：

```sh
python scripts/export-room-maps.py
```

导出器同时生成地图、Scene、通行和 NPC 交互 Story 与 manifest，检查本地图片存在、传送目的地引用、出生点与落点可达，以及 26 个房间连通。直接修改导出 JSON 会在再次导出时被覆盖。

配方的 `packageVersion` 标记整包修订，`stories`
追加手工编写的 Story；这些 Story 已定义的 NPC 交互不再生成空白占位，避免合并冲突。布局物件可声明
`entity`（ID、名称、逻辑格及交互偏移），导出时从静态图层转为实体 sprite，按原像素位置计算偏移；其逻辑格由实体负责阻挡，其余家具占地继续保留。

NPC 来源为 `project-myrmidon-map-prototype/handoff/npc-entities.json` 和
`source/imagegen-v2/assets/npcs/`。重新导入需 Python Pillow：

```sh
python scripts/import-room-npcs.py D:/lab/project-myrmidon-map-prototype
python scripts/export-room-maps.py
```

NPC 在场景中循环播放 idle，每帧使用动作 JSON 的时长和锚点；动画跟随游戏显示时钟，暂停和回放沿用同一时间来源。进入可交互范围后人物高亮，E、点击人物及侧栏按钮共用距离检查。交互菜单提供“闲聊（LLM 待接入）”禁用项、“NPC 动画素材预览”和“离开”。

动画预览复用原型的 idle／talk／duty-1／duty-2 图集、动作名称和逐帧锚点，可选择动作、播放／暂停、切换深浅背景。预览期间世界暂停；Esc 或关闭按钮返回交互菜单，地图中的人物保持原状态。预览选择不写入世界状态或存档。

开始交互时玩家会转向 NPC。现有 NPC 图集是单朝向的动作帧，NPC 的朝向状态虽已更新，四向转身仍需补齐朝向素材。制作顺序为四向站立、四向行走，见 Roadmap。新菜单需要从存档入口开启新时间线加载。

数字生命沿用默认隐藏规则，仅保留素材。NPC 实体放在原脚点附近的可走格，避开门和所有出生／返回点；图片脚点统一对齐实际占用格的中心，使用所在房间的角色倍率，确保画面与碰撞位置一致。

## 坐标与碰撞

原图尺寸与美术摆放保持像素坐标，网格为 32px，每格以中心点和 20×20px 脚底范围取样；房间网格尺寸向上取整。404 的角色倍率在配方中设为当前引擎支持的 3，其余房间沿用来源倍率。原始
`walkable` 多边形提供地板范围，`collisionIds`
明确保留 404 家具、建筑、花坛和固定设备的占地。已移除家具的碰撞不导入空房间。

`art/room-maps.json` 的 `passages` 用 `[列, 行, 宽度格数, 高度格数]`
放置可走通道，在基础碰撞生成后生效，用于门洞和台阶。室外传送物件放在门洞内或台阶阴影中段；下层回廊的检修通道通过南侧独立井口连接。

传送物件由 `art/room-portals.json` 放置，坐标为从 0 开始的 `[列, 行]`。每个 `tiles`
元素放置一个 32×32px 的阴影方块，玩家走入任意方块便传送到 `destination.scene` 的
`destination.anchor`。方块绘制与触发共用这些格子；默认外观由文件顶层 `sprite`
指定，单个物件可用自己的 `sprite` 覆盖。返回落点在对应房间的 `anchors`
中配置，须位于触发区外。导出时计入 NPC 阻挡，逐个检查出生／返回点到各出口的可达性。地图外始终阻挡。

例如，在 404 号舱第 19 列、第 33 行放置一个传送方块：

```json
{
  "id": "return",
  "name": "返回",
  "tiles": [[19, 33]],
  "destination": { "scene": "low-deck", "anchor": "from-enter-404" }
}
```

调整 `tiles`
即可移动或拼接触发区，再运行导出命令。背景图与传送物件独立配置；若房间地板布局改变，同时调整可走区域与落点。

404 背景深度为 -1，地毯在地板层，家具按脚点排序；柜顶和桌面小物使用支撑家具的深度。家具按来源地面占地阻挡，图片上方允许参与遮挡。

404 的床为可交互实体：靠近床尾或右侧下半部时高亮，按 E 或点击床打开交互，选择“睡觉”后使用 1–24 小时滑条，默认 8 小时。确认后推进世界并扣除经过的余时，醒来仍在床边；取消不执行睡眠。除317门牌、404旧记录与暂存柜外，其他物件仍为静态图层。新交互需从存档入口开启新时间线。

## S01：六步强引导调查

新时间线从404开始即显示当前步骤的背景、地点、目标与确认操作。按顺序完成：出门查看317门牌 → 询问Ash
→ 回404右侧书桌读旧记录 → 找右上方N-07核对 → 回回廊取下门牌 → 放入404北侧中央暂存柜。问完Ash只完成第二步，暂存原件后才完成调查。

金色!标记查看／拿取目标，?标记确认／交付目标；目标在另一房间时先标出口。靠近后按E或点击交互，T查看完整记录，1查看门牌背包数量，2回看第1格线索。不需要R等待，也不允许提前确认后续步骤。

拿取会让墙上实体离场并加入背包；交付扣除背包原件并登记柜中暂存。打开、取消对话和切换话题不推进；重复请求不多计，缺物交付全部回滚。实际内容包检查覆盖六步行走、标记切换、背景、步骤限制、取消、缺物和重复请求，并在拿取后恢复存档继续暂存，再检查完成回放。未做浏览器试玩。

## 存档与验收范围

房间地图使用 OPFS
`remaining-time-room-saves`，支持自动恢复、保存、回放与开始新时间线。主线不读取、迁移或删除旧酒馆的
`remaining-time-saves`
和 IndexedDB 存档；酒馆存档仅在实验分支使用。内容变化后需要开启新时间线，房间旧档仍使用其嵌入的内容。

已运行房间包、NPC 占位、自动存档、录制容量与分段回放的针对性检查，覆盖 54 个出口的进入与原路返回、NPC 脚点对齐、路面不误触、台阶通行、厨房出口覆盖，以及容量上限下的连续保存、快照恢复和写盘失败保留进度。

404 资产的逐件对照、回拼与推断区域见资产说明，其余背景沿用现有制作版本。全地图传送点的视觉位置和操作手感尚未完成逐图实机验收，后续跟踪于
[Roadmap](../../../ROADMAP.md#26-房间地图--后续传送点校准)。未运行完整测试或构建。
