# 历史实验：静态内容不可变对照

本目录保留单文件与拆分内容包的对照实验及测试样例。当前实现的版本化说明见
[世界数据模型 · 2026-09-15](https://afterglow.xnnehang.top/architecture/world-model-2026-09-15)。下文是实验时的结论，不代表当前完整能力。本目录比较两种输入组织方式，不表示采用单文件架构，也不涉及 LLM 模型数量。
[world.json](world.json) 仅是单文件对照样例；拆分组读取
`content/fixtures/route/`（固定回归内容）；浏览器 Demo 现为酒馆移动教学。历史实验的两组使用同一个引擎；当前仅保留正式拆分内容包的不可变性与回放检查，位于
`tests/engine/immutable-content.test.ts`，不再维护单文件实验适配器。

## 实验结构

- entities：定义身份对应的外观、movable 与 portal 等属性。
- scenes：地图、anchors、placements（entity ID 与初始坐标）。
- stories：保留整段剧情、选项效果与任务，仍按实体 ID 引用参与者。
- start：初始玩家位置引用。

单个文件只负责静态内容；运行状态由引擎初始化后独立维护。测试中的薄适配器将实体定义与放置合成现有 scene 数据，复用 loadPackage 的校验、合并与运行逻辑。适配器只用于受信任样例，不提供新格式的完整输入校验。

## 已验证

历史实验结果如下；当前回归入口为
`npx jest --runInBand tests/engine/immutable-content.test.ts`，仅覆盖正式拆分内容包。

- 一个 world.json 包含当前双场景、老黑、门、书本、多剧情与并行／顺序任务。
- 老黑给证、格间移动、过门、玩家跟随重逢均通过既有 story 效果执行。
- 内容定义在执行后保持不变。
- 使用相同内容与固定环境，从初始状态逐条重放记录中的命令和 advance(ms)，每一步完整 State 与原运行一致。
- 测试通过；TypeScript 检查通过。运行不包括浏览器视觉或独立编剧 Agent 评估。

## 不能据此宣称

- 不证明完整录制产品已实现；现有 history 含命令、时间推进和调试快照，仍不含内容哈希、引擎版本绑定等发行级日志合同。
- 不证明 snapshot 续播；请求去重缓存等也会影响未来行为，不能只把 inspect() 的 State 写回就认为恢复完整。
- 不证明任意随机／Agent／异步执行可重放；本实验固定时钟与随机源，实际随机结果、外部决策、执行排序仍需纳入正式方案。
- 不证明输入时间可重新分段；现有每 tick 最多到达一格的语义要求重放相同 advance 序列。

## 拆分内容包对照实验

同一测试现在分别加载单文件适配内容与正式 `manifest + scenes + stories`
内容包。两种输入均递归冻结，加载后的定义也冻结；执行器仅能修改自己的运行状态。

两组均通过：老黑离开 room 后仅存在于运行时 corridor；源 scene 的初始位置仍为
[5,5]；另一独立运行仍从 room 初始化；玩家返回 room 不会重新生成老黑。重放每条命令／时间推进后 State 与原记录一致，内容文件对象保持不变。此对照未修改正式加载器或动作接口。

“NPC 决定行动”与“引擎持有权威位置”是不同职责。未来外部决策可提交受校验的领域输入并记录实际结果；不能靠异步直接写坐标来获得自由度，否则无法保证碰撞与重放顺序。本实验仅验证既有剧情驱动移动，不证明 Agent 接口或快照续播可用。

## 能力增长的判断

| 变化                       | 内容表示                 | 引擎工作                             |
| -------------------------- | ------------------------ | ------------------------------------ |
| 改现有对话、路线、任务组合 | 修改 stories             | 无需新增执行能力                     |
| 新增物品交付／活动         | 声明未来注册的动作与事实 | 先实现受校验动作和结果，再开放给作者 |
| 新增 Agent 决策来源        | 声明行为配置（未来）     | 实际决策必须记录，重放消费结果       |
| 恢复运行进度               | 不修改 world 内容定义    | 单独的 replay／snapshot 合同         |

单文件可以承载这些数据，但不会自动实现新能力，也不会自动解决确定性。语言复杂度主要来自任意表达式、隐式覆盖、控制流和动作时序，而非文件数。此预演保持故事线集中编排，实体定义与初始放置分区，不引入继承体系或任意脚本。

结论：两种组织方式均能保持内容不变、状态独立并按相同输入重放。正式入口继续采用拆分内容包；单文件样例用于对照，不作为编剧交付入口。文件合并与否不决定 NPC 自由度或重放确定性。
