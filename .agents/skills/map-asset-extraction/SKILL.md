# 地图资产制作与接入

## 目标与入口

当前建设顺序：先准备各房间空背景与原始布局，接通门、通行和任务，再逐件添加物件。大地图由房间之间的连接组成；空背景阶段的物件 layout 仅作制作参考，不作为可加载资产清单。

物件制作流程：原图矩形取材 → 原子物件规划 → 逐件生成与遮挡补全 → 去底与透视核对 → 标准 PNG 整理 → 场景接入。背景单独补绘。目标是可独立摆放、可按原布局回拼的完整物件，保留来源地图的透视、比例、纹理和光照。

路径相对于本 Skill 目录，项目命令在仓库根目录 `../../..` 执行。先读根目录
`AGENTS.md`，保留与任务无关的改动。读取 [提示词模板](references/extraction-prompts.md)
后填写每次请求；不要直接发送未填写的模板。

正式资产结构见 [404 资产说明](../../../art/props/unit-404/README.md) 和
[资产清单](../../../public/assets/unit-404/layout.json)。已有组合资产记录的是当时制作结果，不是本流程的拆分边界。制作材料存入 Git 忽略的
`art/map-study/<map-id>/`。

## 1. 原图取材与透视记录

- 使用原始地图或已保存的原始
  `room-layout.png`。从已有 layout 坐标或人工观察确定矩形框，向外留出能看清轮廓、接触关系和遮挡者的余量。现有方框足够时无需引入检测模型。
- 输入裁图保留全部原始像素及周边上下文。物件框只定位目标，不作为轮廓遮罩；不用 GrabCut 或已有透明组合图替代原始生成输入，避免把误删、残留和粘连当成真实结构。
- 原图坐标原点为左上角，x 向右、y 向下，单位为像素。记录来源尺寸、裁框
  `[left, top, right, bottom)`、目标在裁图中的框和已知遮挡关系。
- 框太紧或遮挡关系不明时扩大原图裁框；必要时另附整张原图作相机与风格参考。框线、箭头和标签放在独立说明图上，保留一份无标注输入。
- 在生成前用具体可见特征描述透视：长边方向、边线斜率、顶面深度、可见侧面、正面与顶面的比例、竖直方向、脚点及光照方向。不要用泛泛的“俯视”或“等距”取代原图实际相机，也不要把原图自动修正成标准等距视角。

## 2. 由 Agent 规划原子物件

先看原图，列出每个框里的独立可摆放物件，再决定生成请求。一个框可以对应多个资产。

- 原子边界按独立摆放的用途判断，不按连通像素、重叠或接触关系判断。家具、地毯、独立设备、可移动盆栽分别输出；床架与床品、盆与其植物通常保持一件。可移动的柜顶物件按独立摆放需求拆分，不能把整个柜顶默认烘焙到柜子上。
- 每件分配稳定 ID，记录所属来源框、包含的部件、需要排除的邻居、被遮挡的部位、补全依据、尺度参考、脚点和原布局前后层次。建筑与固定装饰按场景需求保留在背景。
- 示例：床／地毯／床边盆栽，拆成 3 件，首轮 3 次生成。冰箱／独立终端／冰箱顶部垂吊盆栽／地面盆栽，拆成 4 件，首轮 4 次生成。地毯补出床下织物与边框；床补出盆栽挡住的结构；冰箱补出终端和植物遮挡的机身；终端补出前景盆栽挡住的下部；盆栽包含完整花盆和属于它的枝叶。
- 默认每次只生成一个目标、一个候选。N 件首轮 N 次请求，各自输入原始裁图；不把前一件生成图当作下一件的来源，不生成多物件拼图再拆分。只有验收不合格的目标需要定向重试，每次说明具体失败点。
- 遮挡补全限于同一视角下应当可见却被邻居挡住的结构，不生成本来背向相机的面。用现有边线、对称性、材质和相邻花纹推断，补绘区必须记录为推断内容。严重遮挡、缺乏证据的结构标记低置信度，先交付候选供审阅，不声称精确恢复原物。

制作计划、每件提示词、原始裁图与生成状态存于本地制作目录。由 Agent 决定常规拆分与请求数量；只有无法从图像或用途判断的关键歧义才向用户澄清。

## 3. gpt-image-2 逐件提取与补全

- 共享调用入口为 [scripts/generate.py](scripts/generate.py)，跨设备配置与命令见
  [image-2 调用说明](references/image-generation.md)，无密钥配置见
  [服务示例](references/image-provider.example.json)。复用配置好的 `gpt-image-2`
  服务；真实凭据和含敏感信息的响应不得落入素材或提交。
- 按模板明确：唯一目标、目标坐标、原子边界、邻居、具体遮挡补全部位、透视特征、可见设计保真要求，以及纯色底输出。保持原有花纹位置、材质、磨损、配色和像素密度。
- 用纯白 `#FFFFFF`
  底生成，四周留白，完整呈现目标。生成时去掉邻居、背景和外部投影，保留物件内部明暗与自身结构；不烘焙由已移除邻居投下的阴影。浅色物件若难以与白底区分，选物件中不存在的均匀纯色并记录。
- 透视是硬约束：保持朝向、投影、边线角度、顶面深度、各可见面的比例和原有透视缩短。完整物件仍应能放回原图的同一位置。相机变化、镜像、旋转或重新设计都判为失败。
- 提示词不能保证像素不变或结构不增减。完成生成后按原图验收，不把“模型遵循了提示词”当作已验证事实。

## 4. 去底、尺度恢复与视觉验收

- 保存生成原图。先去掉从画布边界连通的纯色背景，不能全图删除近白色而误伤家具高光。单独检查椅腿间隙、把手孔洞、叶片间隙等封闭背景区域；只对确认的空隙去底。
- 检查浅色残边、底色污染、杂点、断裂细腿、漏叶、缺角和误透明。阈值去底不是完整验收；有残边时局部去色或修边，结构不合格时重新生成，不以强腐蚀吞掉真实轮廓。
- 先用未遮挡的共同特征求回原图尺度与位置，再检查补全部位。补全后的包围框可能比旧框大，不能强行塞回 GrabCut 的旧尺寸。只允许等比缩放和平移；像素画缩放采用最近邻。需要非等比拉伸、旋转或透视变换才能对齐的候选，退回重新生成。
- 对比至少包含：原始裁图、独立资产的深浅底预览、按原尺度和原遮挡顺序回拼。回拼检查前后物件的接触关系、比例、脚点、图层顺序和是否残留邻居。
- 分开判断边缘、完整性、设计保真与透视。重点核对可见原始区域；隐藏补绘区验证结构合理性，不宣称像素级还原。能回拼不等于可自由摆放，还要单独查看原来被挡住的边界是否完整。
- 每件记录实际生成次数、已查看的对比、推断区域和未通过项。未经视觉核对的候选标记待审阅。

## 5. 标准 PNG 资产

当前阶段直接交付已验收的透明 PNG、布局和来源说明。需要分层修图时再使用 Aseprite；编辑文件作为制作材料留在本地
`art/map-study/<map-id>/`。

| 内容                                                       | 位置与收录方式                                     |
| ---------------------------------------------------------- | -------------------------------------------------- |
| 最终透明物件与背景                                         | `public/assets/<map-or-asset-id>/*.png`，提交      |
| 摆放与来源信息                                             | 同目录 `layout.json` 或现有资产配方，提交          |
| 制作方式、推断区域与限制                                   | `art/props/<map-or-asset-id>/README.md`，提交      |
| 原始房间图与最终总览                                       | 同目录 `room-layout.png`、`overview.png`，按需提交 |
| 裁图、制作计划、提示词、候选、单次制作脚本、遮罩、调试预览 | `art/map-study/<map-id>/`，本地保留                |

跨设备复用的调用脚本随本 Skill 收录在 `scripts/`；共享配置使用 `references/`
下的无密钥示例，真实服务配置保留在用户目录。

- 每件标准资产包含稳定 ID、最终 PNG 和摆放信息。最终 PNG 只存一份。
- 沿用实际清单格式，更新尺寸、局部脚点、原图摆放位置、相对文件引用和拆分关系。来源框与补全后的资产框分别记录；详细推断说明可写入资产 README，不为制作步骤扩展游戏运行时合同。地面占地未知时标记待配置，不从透明边界猜碰撞。
- 原图位置与资产局部脚点分开记录，说明坐标原点与单位；裁切和缩放后同步更新。拆分替换组合资产时检查已有引用，完成新资产验收和引用更新后再清理旧组合。
- 原始房间图保持原始像素；overview 从最终导出 PNG 生成。README 先展示房间图，再展示总览。
- 核对正式 PNG 与已验收透明图的像素一致、尺寸与清单一致。
- 提交前核对暂存路径和体积，只提交标准资产、必要配置、说明及选定对照图。 `.gitignore`
  不会移除已跟踪文件。二进制删除仍留在历史中，未合并资产 PR 按约定 squash；不擅自改写已发布历史。资产提交遵循根目录 AGENTS.md 的 PR 归属约定。

## 6. 空背景补绘

- 移除已拆出的全部可移动物件及其接触阴影，保留建筑、固定装饰、地面纹理、光照和原始透视。提示词、修补范围与候选留在本地。已有认可的背景直接复用。
- 候选与原图尺寸和结构对齐，仅在修补范围内采用生成像素，范围外保持原图。
- 隐蔽地面是重建内容；记录接缝、推断范围与待补区域，最终只保留一份运行时背景 PNG。

## 7. 逐步接入场景

本次包含接入时，读取 [内容包说明](../../../public/content/remaining-time/README.md)、
[manifest](../../../public/content/remaining-time/manifest.json)、
[Scene 能力表](../../../content/SCENE_CAPABILITIES.md) 和
[视觉配置](../../../docs/visual-assets.md)，沿目标 scene 找到地图与加载器。

按当前合同转换原图像素、显示尺寸、脚点和游戏网格坐标，配置碰撞、行走区、出生点、门、交互站位与遮挡。原子资产可独立平移摆放；原始透视贴图不自动支持任意旋转或换视角。只使用引擎已支持的字段，配置缺口单独记录。

按内容包版本约定更新版本，以新时间线验收出生、通行、交互、过门和存档恢复。遵循项目检查范围约定，不因纯资产制作运行无关测试或构建。交付时区分本地候选、标准资产、已接入与已验收，并如实说明未做的检查。工作流维护在本 Skill，协作约定维护在
`AGENTS.md`。
